# Дизайн інсталяції mnemo

> Дизайн інсталяції та підключення. Доповнює `Memory-design-v2.md`

## Підключення проєкту

Основний принцип — підключення виконує Claude Code за визначеною процедурою: детерміновані кроки виконуються скриптами; зміни в уже наявних файлах проєкту — з показом і підтвердженням користувача. Кроки крос-платформні (Linux / macOS / Windows).

## Рівень системи

Основний принцип — рушій (середовище виконання, ембединг-модель, векторний індекс) встановлюється одноразово в домашній директорії користувача, спільний для всіх проєктів, оновлюється незалежно від них.

* Точка входу рушія — лише для автоматизації (хуки, MCP, інсталяційний скіл), не для людини напряму.
* Модель завантажується тільки явним прогрівом, ніколи неявно.
* Індекс — локальний, одноразовий, відтворюваний, не в git.

## Рівень проєкту

Основний принцип — усе, що потрібно проєкту для роботи з памʼяттю, лежить у самому проєкті під git і успадковується кожним, хто його клонує.

* Реєстрація MCP-інструмента памʼяті.
* Хуки: повний reconcile на старті сесії, інкрементально на зміні memory-файлу, авто-підкидання релевантного в контекст.
* Скелет памʼяті: тонкий індекс + директорія логів + topic-файли; агентні блоки по-агентно.
* Виклики у git-tracked налаштуваннях — портативні, без машинно-залежних шляхів.

## Крос-платформність

Основний принцип — один і той самий проєкт і той самий git-tracked wiring
працюють на Linux, macOS і нативному Windows; відмінності інкапсульовані в
інсталяторі рушія й у способі, у який ОС резолвить портативний шлях.

* Інсталятор рушія — платформозалежний, контракт однаковий: `install.sh` на
  POSIX; `install.ps1` на нативному Windows (вбудований PowerShell 5.1+,
  64-бітний Python 3.10+; без WSL, PowerShell 7 чи запису в PATH). Параметри
  Windows-інсталятора: `-Check`, `-InstallHome`, `-Python`; типовий і
  канонічний дім рушія — `%USERPROFILE%\.claude\mnemo`. `-InstallHome`
  призначений для ізольованих перевірок або ручних запусків: portable project
  wiring завжди звертається до канонічного дому.
* Точка входу рушія — один логічний шлях `~/.claude/mnemo/bin/mnemo`: на POSIX
  це безрозширенний Bash-лаунчер, на Windows — справжній `bin\mnemo.exe` (ОС
  сама дорезолвлює безрозширенний шлях до `.exe`).
* Портативний wiring без машинних шляхів: хуки у shell-формі
  `~/.claude/mnemo/bin/mnemo <subcmd>` (шелл розкриває `~` для кожного
  користувача); `.mcp.json` — `command: ${HOME}/.claude/mnemo/bin/mnemo`,
  `args: ["mcp"]` (Claude Code підставляє власний `$HOME` кожного тімейта).
* Windows-інсталятор задає користувацьку змінну `HOME` лише якщо її ще немає
  (щоб `${HOME}` резолвився), ніколи не перезаписує її та відмовляється
  продовжувати, якщо вона відрізняється від PowerShell `$HOME`/`%USERPROFILE%`:
  і MCP, і hooks мають вказувати на один дім. Після першого створення `HOME`
  треба закрити й знову відкрити термінал або IDE, з якого запускається Claude
  Code, а потім перезапустити Claude Code.
* Визначення кореня проєкту в рантаймі — однакове всюди: явний `--root` >
  `MNEMO_ROOT` > `CLAUDE_PROJECT_DIR` > поточна директорія; відносні
  ідентифікатори проіндексованих файлів завжди використовують `/`, тому вони
  не розходяться між платформами лише через різні роздільники шляхів.
* Модель, як і раніше, завантажується лише явним прогрівом (`warmup`, ~2.2 ГБ),
  ніколи неявно — на всіх платформах.

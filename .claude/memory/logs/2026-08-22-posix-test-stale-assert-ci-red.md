# 2026-08-22 — CI був червоним 6 прогонів поспіль: тест не наздогнав власний фікс

Продовження `logs/2026-08-21-posix-test-and-uninstall-survey.md`.

## Симптом

Знайдено через GitHub Actions UI (не через локальний прогін — цей тест
пропускається на Windows, `os.name == "nt"`): CI на `feat/v3` падав з run
#20 по #25 (6 прогонів), незмінно на Ubuntu (3.12 і 3.10) та macOS, Windows
завжди зелений.

## Причина

`f9a4941` (21.08) навмисно залишив у `tests/test_install_posix.py:313`
assert зі старим значенням `"src/, launcher, requirements"` і задокументував
це як відомий розрив: на той момент `uninstall.sh`'s survey-рядок ще не був
мігрований під версійну розкладку (`current`/`versions`), тож насправді
завжди друкував `"MISSING"`, і тест це не міг перевірити чесно.

Той розрив закрив наступний комміт того ж дня, `e74fcb0` (задокументований
у попередньому логу) — `uninstall.sh` тепер друкує
`"src/, launcher, requirements (versions/, current)"`, той самий формат, що
й `uninstall.ps1`. Але **сам тестовий assert і пояснювальний коментар не
оновили разом з цим фіксом** — лишився чекати старий, тепер уже неправильний
текст без суфіксу. Тест власного попередження не пережив: розрив, який він
сам зафіксував, закрився, а очікування — ні.

## Фікс

`tests/test_install_posix.py:313` тепер очікує
`"src/, launcher, requirements (versions/, current)"` — реальний, вже
правильний вивід `uninstall.sh` після фіксу `e74fcb0`. Застарілий
багаторядковий коментар-пояснення розриву прибрано, замінено одним рядком,
що вказує на комміт-фікс.

## Урок

Коли комміт навмисно документує "тест зараз перевіряє правильне значення,
а код ще ні" — це створює приховану залежність: наступний комміт, що
лагодить той код, зобов'язаний і оновити коментар/лишити assert як є (тут
буквально не треба було чіпати сам assert, лише прибрати застарілий
коментар), інакше зелений CI одразу після фіксу — це просто ще не
доїхавший push, а не підтвердження. Тут проміжок був майже добу (6 пушів),
перш ніж хтось помітив червоний CI.

Не спіймано жодним локальним прогоном на цій машині (Windows) — тест
пропускається тут за конвенцією (`test_install_posix.py`/`test_install_windows.py`
не діляться кодом, POSIX-пара перевіряється лише в CI). Знайдено виключно
переглядом GitHub Actions UI за прямим проханням користувача.

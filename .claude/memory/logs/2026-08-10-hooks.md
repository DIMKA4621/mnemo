# 2026-08-10 (четверте) — хуки видалено, правило посилено, дисципліна перевірена

Коміт: `feat!: delete the hook seeds; the rule alone requires searching first`.

## Що прибрано

`--with-memory-hook`, `--with-inject-hook`, команди `mnemo memory-hook` і `mnemo hook-inject`, `_HOOK_SEEDS`, `_retired_for`, параметр `hooks` у `init_project`, `INJECT_TOP_N` у конфізі.
`_plan_settings` лишилася з одним завданням — **знімати** хуки під `--migrate`.

`_RETIRED_HOOKS` тепер чотири пари: v2 `ingest` і `hook-postedit`, ранній v3 `hook-inject`, середній v3 `memory-hook`.

`hook-postedit` **лишається** — це шим, який існує рівно щоб вписаний колись хук не падав.
Видалити його = спричинити те, від чого він захищає.

## Чому обидва, а не тільки авто-інжект

`hook-inject` шкідливий із самого початку: віддає памʼять **до** того, як задачу сформульовано, і агент вважає, що вже шукав.

`memory-hook` віддавав **чесну мапу**, а не відповіді, і саме тому жив довше.
Прибраний з іншої причини: ту саму мапу віддає тул `tree` **на вимогу**, а мапа, що приходить непроханою, конкурує з правилом, яке каже піти й подивитися.

Наслідок, заради якого це й зроблено: дисципліна записана **в одному місці**.
Два механізми, що кажуть одне й те саме, можуть розійтися, і виграє той, якого ніхто не редагує.

**Факт, який варто памʼятати:** у цьому проєкті хуків не було вписано **ніколи** — `.claude/settings.json` містив лише `env`.
Усе, що працювало, працювало з правила.
Тобто видалення нічого не зламало, бо нічим і не користувалися.

## Правило переписане: пошук — умова за замовчуванням

Було: список тригерів («шукай перед плануванням, перед зміною архітектури…»).
Стало: **кожне** повідомлення користувача, яке щось питає, вирішує чи змінює, **починається** з `search`.
Виняток один — повідомлення без питання й без рішення («запусти тести», «коміть», «так»).

Додано три речі:

- «**Не відповідай зі своїх знань, доки не подивився.** Твоє тренування не містить цього проєкту.
  Те, що памʼятаєш із розмови, теж не доказ.»
- **Асиметрія**: пошук, який нічого не знайшов, коштує секунду; пропущений пошук коштує проєкту суперечності, і помітити її має користувач.
- «**Скажи, що шукав**» — рядком, що саме шукав і що знайшлося.
  Це те, що дозволяє читачеві відрізнити відповідь, підперту записом, від тієї, що просто звучить упевнено.

## Перевірено живою сесією, а не самозвітом

Дві headless-сесії `claude -p` у цьому проєкті.
**Обидві шукали першою дією** і обидві почали відповідь із рядка «шукав у памʼяті: …».
Підтверджено **журналом** (`mnemo logs`), а не словами агента:

```
15:02:05  mcp  ready  n=4  чому в MCP URL немає сегмента банку, токен = адреса банку
15:02:05  mcp  ready  n=3  per-bank token MCP face bank parameter removed decision
15:03:09  mcp  ready  n=6  MCP tools search tree read file viewer
15:03:09  mcp  ready  n=4  чому немає інструмента read/get file у MCP, рішення про набір
```

Друга сесія (запит «заплануй новий MCP-тул») зробила те, заради чого памʼять і потрібна: знайшла в контрактах §10.2 «`search` / `tree` — рівно ці два, і більше нічого», і **зупинилася**, сказавши, що це не «додати функцію», а зняти зафіксоване рішення, і що потрібна явна згода.
Без пошуку вона б просто спроєктувала тул.

Дві сесії — це демонстрація, що механізм працює, **не** статистика.
Наскільки дисципліна тримається на складніших і довших задачах — окреме питання.

# 2026-08-28 — «Агенти»: реєстр/agent-settings mockup rework + PTY-термінал POC

## Реєстр + налаштування агента (mockup rework, `.claude/scratch/agents-page-mockup/`)

Через `ui-dev` субагента (попередній `agents-page-mockup` процес зник після перезапуску машини/браузера — новий `agents-page-mockup-v2` продовжив з чистого контексту, повний переказ вимог у промпті):

- Реєстр: кнопку «Сканувати» прибрано повністю. Лишилась тільки «+ Додати» — ручне додавання (назва + конфіг/текст), з live-парсингом `{{VAR}}`-плейсхолдерів із конфігу (debounce), JSON-валідністю (inline-помилка, дизейблена кнопка) і дедуп-перевіркою за нормалізованим конфігом (не можна додати другий MCP з ідентичним конфігом).
- Кожен запис реєстру (MCP і Skills/Rules) редагується на місці — олівець → textarea, та сама жива логіка (перерахунок змінних, JSON-валідність, дедуп проти інших записів).
- Налаштування агента (⚙) → вкладка MCP/Skills/Rules переписана: три незалежні підрозділи (MCP-сервери/Skills/Правила), кожен показує **лише приєднане до цього агента** (не весь реєстр). «Змінити» вмикає edit-mode окремо по кожному підрозділу — смітник на рядку + «+ Додати» знизу. «+ Додати» відкриває вибір лише з непри-єднаних записів реєстру → крок 2: локальна назва (редагована, дефолт з реєстру) + значення шаблонних змінних (лише для цього агента, реєстр не чіпається).

Усе перевірено особисто через `chrome-devtools-mnemo` (порт 9946) перед доповіддю користувачу — включно з live JSON-валідністю (зіпсований конфіг → inline помилка, дизейблена «Зберегти») і повним циклом «+ Додати» → крок 2 → зʼявляється в списку зі значеннями inline.

**Відкрито:** заголовок самої вкладки в agent-settings досі «MCP / Skills / Rules» (мішана мова), хоч підрозділ усередині вже «ПРАВИЛА» — не уніфіковано, користувач ще не підтвердив, чи важливо це виправляти.

## PTY-термінал POC (`.claude/scratch/claude-terminal-poc/`)

Дослідницьке питання користувача: чи можна показати РЕАЛЬНИЙ термінал `claude` CLI (не структуровані SDK-події) у браузері. Дельоговано `general-purpose` субагенту, послідовність навмисна — спершу нешкідливий `cmd.exe` (перевірка сантехніки PTY↔WS↔xterm.js), тільки потім реальний `claude`.

Результат — див. `topics/agents-feature.md` (розділ «Рантайм агентської сесії»): підхід підтверджено живим тестом зі скріншотами (перевірено особисто, не лише зі слів субагента), обрано як основний рантайм майбутньої консолі агента.

Побічно зʼясовано: `CLAUDE_CODE_CHILD_SESSION` — self-виставлена env-змінна самого CLI при виявленні вкладеності в process tree, вимикає збереження транскрипту вкладеної сесії. Не є каналом звʼязку між сесіями.

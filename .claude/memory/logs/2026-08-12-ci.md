# 2026-08-12 (друге) — CI був червоний з першого ж прогону, і причин три

Коміт: `fix(scaffold): make the shell half substitute literally on every bash`.

## Симптом

Усі шість прогонів GitHub Actions (від 2026-07-30, відколи є `ci.yml`) —
failure, і завжди в одній матриці: **ubuntu ✅, windows ❌, macos ❌**.
Локально на цій же Windows-машині — 200/200.

Отже пояснення не в «Windows»: воно в тому, чого локальна Windows **не має**,
а CI і macOS мають. Таких речей виявилось три, і вони незалежні.

## 1. Тест звіряв обхід із нерезолвленим `tempfile`-шляхом

`test_index_paths` віддавав у `scan_bank` **резолвлений** корінь
(`config.resolve()` кличе `Path.resolve()`), а звіряв із **нерезолвленим**
`root` від `tempfile`:

```python
all(walk[v].abs_path == root / v for v in identifiers)   # було
```

Збігаються вони лише там, де тимчасова тека — справжній шлях. На ранері
`TEMP=C:\Users\RUNNER~1\…`, і `resolve()` розгортає 8.3 у `runneradmin`; на
macOS `/var/folders/…` → `/private/var/folders/…`; у нас `dima` коротше за
8 символів, тож скорочення немає й тест зелений.

Вада **тесту**, не продукту: `scan_bank` послідовно повертає `abs_path` під
тим коренем, який отримав. Відтворюється локально за 30 секунд — junction і
підміна `TEMP`/`TMP`:

```powershell
New-Item -ItemType Junction -Path "$env:TEMP\ci-link" -Target "$env:TEMP\ci-real"
$env:TEMP = "$env:TEMP\ci-link"; $env:TMP = $env:TEMP
```

## 2. `mcp-setup.sh` ламав JSON на macOS — вада ПРОДУКТУ

Це найважливіше, бо їде до користувачів. На macOS `/bin/bash` — досі **3.2**,
і в ньому `${var//"pat"/"repl"}` лишає лапки **заміни** літеральними
символами. Тобто кожне підставлене значення приїжджало в файл обгорнуте в
`"`, і `.mcp.json` виходив невалідним JSON:

```
"url": "http://"127.0.0.1":8918/mcp?token=…"
```

Арифметика збіглася точно: 409 проти 395 байтів = 7 підстановок × 2 лапки.
Далі тест викликав `json.loads` — і **суїта падала з трейсбеком просто
посеред себе**, тому в macOS-лозі видно лише 128 PASS і жодного підсумку.
(Це, до речі, окремий висновок: `json.loads` у тесті без `try` перетворює
одну ваду на «решта перевірок не існує».)

**Перша спроба фіксу зробила гірше, і саме це варте памʼяті:** зняти лапки із
заміни. Bash **5.2** підставляє на місце неекранованого `&` у заміні той
текст, який щойно збігся, — і значення `a|b&c$1d/e` перетворилось на
`a|b{{ODD_VALUE}}c$1d/e`. Тобто дві поведінки дивляться в **протилежні**
боки, і однією формою `${//}` їх не помирити:

| bash | `${v//"p"/"r"}` | `${v//"p"/$r}` |
|---|---|---|
| 3.2 (macOS) | лапки заміни лишаються в тексті | ✅ |
| 5.2 | ✅ | `&` розкривається у збіг |

Тому підстановку переписано на функцію `substitute()`, яка ріже рядок по
голці (`case` + `${hay%%"$needle"*}`) і склеює. Ні шаблонів, ні посилань на
збіг — нічого, що якийсь bash може прочитати по-своєму. Присвоює в
`$REPLACED`, а не друкує, бо `$(...)` зʼїдає кінцеві переноси.

Наслідок, який лишається відкритим: `init` **не оновлює** свій
`mcp-setup.sh`, якщо той уже несе маркер `mnemo:dynamic-setup/1` («нічого
додавати»). Тобто проєкти, adopted до цього фіксу, лишаються зі старим
скриптом назавжди. На Windows/Linux це нешкідливо (там стара форма
працювала), на macOS — ні. Полагодити можна бампом маркера до `/2` і
переписуванням власного скрипта; **не робив, бо це зміна поведінки `init`.**

## 3. `bash` на Windows-ранері — це не bash

`note  mcp-setup.sh exited 1:` з **порожнім** stderr, і слідом `parity check
skipped: no usable bash`. Причина: у `PATH` ранера `System32\bash.exe`
(лаунчер WSL) стоїть **перед** Git Bash, а без дистрибутива він виходить з 1
і нічого не пише в stderr.

Найгірше тут не падіння, а те, що з трьох перевірок «скрипт має голосно
впасти на відсутній змінній» дві **пройшли вхолосту**: код ≠ 0 і файл не
написаний — рівно те, чого тест і чекав, тільки причина інша. Тепер тест
**пробує** bash (`-c 'printf ok'`), бере Git Bash явно, якщо PATH-овий не
відповідає, і друкує, яким саме bash та якої версії він скористався.

## Як читати логи Actions (щоб не витрачати час удруге)

- Анонімно **доступно**: `/actions/runs`, `/actions/runs/{id}/jobs` — тобто
  які кроки в яких матрицях впали. Цього вистачає, щоб звузити коло.
- Анонімно **закрито**: текст логу. І API (`403 Must have admin rights`), і
  веб («Sign in to view logs»). `gh` на машині немає.
- Робочий шлях — **браузерний профіль по CDP** (`chrome-devtools` MCP), і в
  ньому має бути **логін у GitHub** (у нашому профілі його спершу не було —
  там Upwork і Vast, а GitHub ні).
- Сам лог кроку віддає не сторінка, а редирект на підписаний blob:
  `GET /<owner>/<repo>/commit/<ПОВНИЙ-sha>/checks/<check_run_id>/logs/<номер кроку>`
  → 307 → `productionresultssa*.blob.core.windows.net/...`. Скорочений sha дає
  500, без номера кроку — 404. `check_run_id` = `id` джоба з `/jobs`.
- Витягати текст зі **сторінки** марно: лог віртуалізований, скрол губить
  рядки (зібралось 110 із 220, і підсумковий рядок не потрапив).

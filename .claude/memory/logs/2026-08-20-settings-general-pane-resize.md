Два прямих правки за скріншотами живого кабінету (dev server, не реальний сервіс — той досі роздає старий мірор до наступного `install.ps1`).

## 1. Settings: «Служба» → «Загальні», тема нагору, порядок вкладок

Розділ перейменовано з «Служба» на «Загальні» й переставлено **першим** (було другим, між «Модель ембедингу» і «Обслуговування»; тепер: Загальні → Модель ембедингу → Обслуговування).
Усередині розділу порядок теж змінився: **тема кабінету** тепер перша, **автозапуск** друга, стан процесу (версія/PID/адреса/провайдер/uptime/черга) і попередження про зупинку — знизу, після обох контролів.

**Знайдений і виправлений баг: тема виглядала «розтягнутою рядком таблички», хоча автозапуск поруч — ні.** Обидва контроли — `.segmented`, але `renderAutostart` рендерив `.segmented set-toggle`, а `renderTheme` — голий `.segmented`.
`.set-toggle { align-self: flex-start; }` — це те, що тримає контрол по ширині вмісту всередині `.set-field` (flex-column, де діти за замовчуванням `stretch`); без цього класу тема розтягувалась на всю ширину форми й читалась як рядок таблиці, а не як перемикач.
Один клас, візуальна паритетність відновлена.

Функції перейменовано услід за розділом: `renderServiceSection` → `renderGeneralSection`, `submitService` → `submitGeneral`.
`SETTINGS_SECTIONS` id — `service` → `general`; дефолтна вкладка при відкритті сторінки (`settings.section`) теж стала `general` (була `embed`) — логічно, бо тепер це перша вкладка.

## 2. Памʼять: три заголовки колонок різної висоти → однакова

**Причина, не симптом:** `.pane-head` мав `min-height: 34px`, а не фіксовану висоту.
Три заголовки несуть різний вміст — «Банки» лише іконку-кнопку (↻), «Файли» голий текст + `.pane-sub`, «Вміст» чекбокс + кнопку «Переіндексувати файл» (найвищий елемент, ~22-24px).
`min-height` клампить лише найкоротший; два інших ростуть по висоті свого найвищого дочірнього елемента понад мінімум — звідси видима різниця.
Виправлення: `height: 37px` (фіксовано, не `min-`) — досить, щоб вмістити найвищу кнопку, і `align-items: center` центрує решту.
Виміряно `getBoundingClientRect()` для всіх трьох заголовків після фікса: `[37, 37, 37]` — рівно.

На вузьких екранах (`max-width: 620px`, де `.pane-head` вже отримував `flex-wrap: wrap` для переносу вмісту на два рядки) фіксована висота скасовується назад на `height: auto; min-height: 34px` — інакше вміст, що переноситься на другий рядок, обрізався б.

## 3. Памʼять: колонки Банки/Файли тепер тягнуться мишкою

Раніше `.layout` — CSS grid з жорсткими `300px 300px minmax(0,1fr)` (плюс окремий брейкпоінт 1180px, що стискав до `270px 262px`).
Тепер два draggable-роздільники (`.pane-resizer`, 6px, `cursor: col-resize`) — реальні grid-колонки між панелями, не оверлей: `grid-template-columns` стало `<w1>px 6px <w2>px 6px minmax(0,1fr)`.
Третя колонка (Вміст) завжди займає залишок — трекається й зберігається лише `[w1, w2]`.

- Драг — звичайні `mousedown`/`mousemove`/`mouseup` на `document` (не на самому 6px хендлі, щоб швидкий рух миші не «зіскочив» з вузької смуги посеред жесту); межі — `clamp(180, …, 640)` px на кожну колонку.
- Персиститься в `localStorage['mnemo_pane_widths']` як `[w1, w2]` — той самий патерн, що `mnemo_theme`/`mnemo_sidebar`.
  Відновлюється **не до першого пейнту** (на відміну від теми): це невеликий resize, не колірний спалах, тому не потребує inline-скрипта в `<head>`.
- Брейкпоінт 1180px (270/262) прибрано як мертвий код: inline-стиль від JS все одно завжди переважає медіа-запит, тож автоматичне звуження втратило сенс — тепер користувач звужує сам, якщо вікно вузьке.
  На <940px (мобільний однопанельний режим) `.pane-resizer { display: none }` — тягнути нема що.

Перевірено в браузері (chrome-devtools MCP, dev server):
- реальний драг через синтетичні mouse-події — ширина міняється живо, зберігається в `localStorage`, переживає `reload`;
- відсутність збереженого значення (`removeItem` + reload) повертає дефолтні `300/300`;
- обидві теми, 760px (мобільний однопанельний режим — резайзери сховані, нічого не ламається), `node --check` на обох змінених JS-файлах.

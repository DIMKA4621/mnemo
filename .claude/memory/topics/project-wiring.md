# Проводка проєкту: що пише `init` і чому саме так

Усе, що mnemo кладе в чужий репозиторій. Поверхні служби —
`topics/service-surfaces.md`; встановлення рушія — `topics/install-lifecycle.md`.

## Ключ запису MCP — `mnemo-memory`

Тули стають `mcp__mnemo-memory__search`; лишається місце для **другого**
запису на інший банк.

Старий ключ `mnemo` **перейменовується, а не доповнюється**: наш HTTP-запис
переносить звичайний `init`, stdio-покоління — `--migrate`, **чужий** сервер
із такою назвою не чіпається. Префікс змінних лишився `MNEMO_` навмисно.

## Другий банк кладеться руками з консолі

Команди для цього свідомо **немає**: `init` означає рівно «памʼять цього
проєкту».

**Персональний лише токен** (`MNEMO_TOKEN`, `MNEMO_NOTES_TOKEN`) — інакше
другий банк затер би токен першого. `MNEMO_HOST` / `MNEMO_PORT` спільні, бо
це адреса **служби**, а не банку, і копія на кожен банк розходилася б щодо
єдиного факту.

## `.mcp.json` генерований і gitignored

У git їде `.mcp.json.template` + `.mcp.env.example` + `mcp-setup.sh` / `.ps1`.
**`init` будує цей шар сам, у будь-якому проєкті.**

Відстежений `.mcp.json` він не просто відкидає, а **питає згоди й робить
`git rm --cached`** (без термінала — нічого не робить і друкує команду;
`--yes` для скриптів). Шаблон **починається з наявного `.mcp.json`**, інакше
чужі сервери зникали б на першій перегенерації.

## `init` сам запускає `mcp-setup` — регенерація більше не ручний крок

2026-08-20: раніше `init` лише друкував «regenerate .mcp.json with either
of: bash mcp-setup.sh / powershell ... mcp-setup.ps1» і зупинявся — саме той
ручний крок, який користувач і так завжди робив одразу після `init`
(`cp .mcp.env.example .mcp.env` → `init` → `bash mcp-setup.sh`, задокументовано
вище/`logs/2026-08-11-migration.md`). Тепер `init_project()` виконує цей крок
сам, останнім у собі: `_run_setup_script()` (`scaffold.py`) запускає
`mcp-setup.ps1` через PowerShell на `os.name == "nt"`, інакше — `mcp-setup.sh`
**напряму через shebang** (не шукає `bash` на PATH — той пошук у тестах
існує лише через WSL-заглушку в Windows CI, на реальному POSIX хості
зайвий).

**Інваріант не порушено:** `_plan_wiring()` і далі ніколи не кладе
`.mcp.json` у власний план записів — новий крок стартує вже ПІСЛЯ того, як
усі файли записані, і буквально запускає той самий скрипт, який користувач
запустив би сам. `.mcp.json` як і раніше пише лише скрипт, лише один шлях —
просто тепер його викликають автоматично, а не руками.

Невдача (скрипт `edited`-стану зламаний, раннер не знайдено) **не валить
`init`** — `init_project()` все одно повертає `0`, а стара інструкція
«regenerate .mcp.json by hand with either of: ...» друкується як фолбек із
діагностикою помилки. Мертвий кутовий випадок (шаблон є, а скрипта для цієї
платформи нема) лишає старий текст без спроби запуску.

Виконується і всередині FastAPI/uvicorn (чекбокс у консолі «одразу
підключити проєкт (MCP)», нижче) — без термінала, тож `subprocess.run` там
несе `creationflags=CREATE_NO_WINDOW` на Windows (`0x08000000`, той самий
константний прийом, що `service_ctl._windowless_kwargs`, але власна копія в
`scaffold.py` — модуль-приватне число не тягнеться крос-модульно).
`_run_init_for_bank`/`api.py` нічого не парсить із виводу `init` (просто
рядки stdout), тож нові рядки в лозі — чистий виграш без змін бекенду.

**Тестування:** перший наскрізний тест `init_project()` у суїті
(`test_init_runs_setup_script`, `test_init_setup_script_failure_falls_back`)
— усі попередні тести білі `_plan_wiring`/`_plan_mcp_template` напряму й
ніколи не викликали `init_project()`. Безпечний спосіб уникнути пастки
автоспавну реального сервісу (наступна секція нижче й `topics/deferred.md`):
**мокати `src.client.Client` цілком** (`patch("src.client.Client")`, а не
просто вказувати недосяжний порт) — недосяжний порт із `autostart=True` сам
підіймає реальний `mnemo service serve`, а підмінений клас `Client` узагалі
не йде в мережу.

## Broad ignore більше не ховає памʼять мовчки

Після seed `init` запускає read-only `git check-ignore -v` на
`MEMORY.md` і правило памʼяті. Якщо `**/.claude` чи інше правило їх ховає,
він **не переписує** людську політику `.gitignore`, але називає match, каже
«NOT ride with a commit» і дає вузькі винятки + `git status` для перевірки.

Пастка тесту: verbose-вивід показує й **negation**, що врятувала шлях
(`!.claude/memory/**`). Непорожній stdout не означає ignored — pattern із `!`
треба відкинути. Tracked файл git за замовчуванням не показує, і це правильно:
він уже їде з комітом.

## Скрипти динамічні, а не з переліком

Підстановки **вичитуються з шаблону**, не перелічуються по одному `sed -e`.
Відсутня змінна = **іменована помилка й ненаписаний файл**; раніше це був
дослівний `{{TOKEN}}` у `.mcp.json` при `exit 0`.

Новий банк = запис у шаблон + токен у `.mcp.env`, більше нічого.

Дві половини (bash / PowerShell — бо нативній Windows нізвідки взяти bash)
тримає тест на **байтову** рівність. Маркер `mnemo:dynamic-setup/1` відрізняє
наш скрипт від чужого.

## Змінних три

`MNEMO_HOST`, `MNEMO_PORT`, `MNEMO_TOKEN` — плейсхолдер на **кожній** змінній
позиції URL. Хост додано, бо `MNEMO_API_HOST` налаштовний, а літерал у
git-трекнутому шаблоні не перевизначався. Дописує їх **звичайний** `init`
разом із рядком `sed`; без цього плейсхолдер їде в `.mcp.json` дослівно, а
скрипт виходить з 0.

## Правило оновлюється тихо, якщо його не правили

`init` звіряє sha256 байтів `mnemo-memory.md` зі списком **усіх** редакцій,
які mnemo писала — **дві форми на редакцію**: до `_write` файл ішов через
`write_text`, тож Windows-проєкти мають CRLF. Невідомий хеш = чиясь правка,
не чіпається. `MEMORY.md` — **ніколи** (це курований вміст).

**`_rule_state` = `edited` не означає «хтось правив руками»** — лише «байти не
збігаються з жодною нашою редакцією». Забути дописати дайджест у
`_RULE_SUPERSEDED` = **мовчки вивести проєкт з-під оновлень правила**. Так уже
сталося: коміт про `mnemo-memory` оновив файл у репо й лишив константу казати
`mnemo` (полагоджено, редакція **v6**).

## Хуків немає жодних

Рішення #27: ні `--with-memory-hook`, ні `--with-inject-hook`, ні самих
команд. Дисципліна живе в одному місці — `.claude/rules/mnemo-memory.md`, і
правило вимагає `search` **перед** кожним питанням, планом чи зміною, а не за
списком тригерів.

## Скіл `mnemo-adopt` лишається, але без опису проводки

Він був **другим source of truth** про те, чим володіє `init`, — і протухав
першим, бо ніщо його не перевіряє. Тепер: «`init` володіє проводкою повністю,
читай його вивід».

Скілу лишилися чотири судження, яких командою не зробити: тріаж `CLAUDE.md`,
склад ролей, прапорець команд агентів, міграція вбудованої памʼяті.

## Рантайм агентської сесії: два перевірені підходи, обрано другий

**Підхід A — Claude Agent SDK, структуровані події** (`.claude/scratch/agents-sdk-poc/`, перевірено 2026-08-25/26): `ClaudeSDKClient` з `cwd=...`, `include_partial_messages=True`, стрім подій (`ThinkingBlock`/`ToolUseBlock`/`TextBlock`/...) у браузер через WebSocket. Працює, реальний `cwd`-байндинг підтверджено. **Мінус:** кожен UI-елемент (thinking-індикатор, картка tool-call, стрімінг тексту, слеш-команди) треба вручну перевикидати під формат SDK-подій — і так назавжди, при кожній новій фічі CLI.

**Підхід B — справжній `claude` CLI у PTY, дзеркалиться байт-в-байт** (`.claude/scratch/claude-terminal-poc/`, перевірено 2026-08-28) — **обрано як основний**. Реальний бінарник `claude` (той самий CLI користувача) підключений до справжнього псевдотерміналу, вивід дзеркалиться в браузер через WebSocket у [xterm.js](https://xtermjs.org/) (той самий рушій, що в VS Code/code-server).

- Windows: `pywinpty` (обгортка ConPTY, активно підтримується, реліз 2026-01) — `PtyProcess.spawn([shutil.which("claude")], cwd=..., dimensions=(rows, cols))`.
  POSIX-еквівалент не перевірявся ще (стдлібний `pty` модуль або `ptyprocess`, по аналогії).
- Живий тест: рендер у браузері **піксель-в-піксель ідентичний** нативному терміналу — ASCII-лого, статус-бар (модель/контекст%/usage/auto-mode), інтерактивна навігація стрілочками по MCP-consent екрану, реальна відповідь на тестовий запит (`2+2=?` → `4`, "Brewed for 3s"). Resize через `addon-fit` + `proc.setwinsize(rows, cols)` — без проблем при 54×245.
- **Перевага підходу B:** повна пожиттєва feature-parity без жодного ручного перевикидання UI — усі слеш-команди, самооновлення, майбутні фічі CLI працюють автоматично, бо це буквально той самий бінарник.
- **Нюанс, знайдений живцем:** вкладений `claude` сам виявляє себе як дочірню сесію (`CLAUDE_CODE_CHILD_SESSION` env var, виставляється самим бінарником, коли в process tree вже є інший `claude`-процес) і сам вимикає збереження транскрипту. Це **не** канал звʼязку й не усвідомлення «хто його запустив» — просто самозахист від колізій транскриптів. Реальна крос-сесійна обізнаність (агент А знає про агента Б, може надіслати повідомлення) — окремий шар, ще не побудований, див. `docs/Agents-v1-scope.md` §5 (мультиагентність).
- **Кожен реальний виклик `claude` усередині PTY — реальне використання підписки**, не фейкові дані (як і сам Підхід A). Тестувати ощадно.

Обидва POC лишаються робочими для звірки; продуктове рішення — Підхід B для основної консолі агента. Підхід A може знадобитись окремо, якщо колись треба буде програмний доступ до структурованих подій (не просто відображення), а не як основний рантайм UI.

## Фронтенд-стек (для контексту рішення «як вкладати макети в реальний код»)

`src/webui/static/` — **vanilla JS + CSS, без фреймворка, без білд-степу/бандлера** (свідоме рішення проєкту, детально — `topics/console-ui.md`). `<script src>` у порядку завантаження (`app.js` → `shell.js` → `page-*.js`), CSS розбитий на `styles/*.css`, дизайн-токени — CSS custom properties в `base.css`. Мокапи (`.claude/scratch/agents-*`) навмисно копіюють ті самі токени, щоб реалізація була прямим перенесенням, а не редизайном.

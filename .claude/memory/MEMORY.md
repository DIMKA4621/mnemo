# mnemo project memory

Bank root: `.claude/memory` (this folder), searchable through the `mnemo` MCP
server — the `search` tool. This file is an **index**: links + quick facts only;
detail lives in `topics/`, day notes in `logs/`.

## Architecture

- [Native Windows support](topics/windows-native-support.md) — PowerShell 5.1
  installer, canonical launcher contract, portable wiring, and verification.
- [Пропускна здатність ембедингу](topics/embedding-throughput.md) — наш
  CPU-резидент проти bge-m3 на GPU через Ollama, на однакових 35 571 токені:
  **8.8× на пакеті, але лише 1.8× на одному запиті**. Плюс свіп батча (CPU і
  GPU хочуть протилежного) і головна знахідка: **час індексації = паддед-
  токени / 243**, тобто сортування чанків за довжиною дає +14% пофайлово і
  **+85% наскрізно**, а сьогодні більше половини часу йде на паддінг.
  Там же — чому `CHUNK_CAPACITY` тримає максимум під вікном e5 у 512
  токенів, і recall трьох пар (модель × рантайм): **усі три однакові, бо
  `test_search.py` — поріг регресії, а не інструмент порівняння**.
- [Машинні налаштування і другий провайдер](topics/provider-settings.md) —
  `state/settings.json` (env > файл > дефолт), Ollama як конфігурація вже
  запланованого `api`, чому зміна провайдера **завжди** тягне повну
  перебудову (збіг розмірності — найнебезпечніший випадок), керування
  резидентом у кабінеті, і чому Docker поки ні.

## Quick facts

- Сторінці **не можна** дізнатися шлях до вибраної теки (`webkitdirectory` —
  лише відносні імена; `showDirectoryPicker()` шлях приховує навмисно). Тому
  вибір теки в кабінеті обходить ФС **на боці бекенда** — `GET /api/fs/dirs`.
  Нативний системний діалог відкинуто (contracts §14, п.5).
- Памʼять цього проєкту **переїхала в репозиторій** (`.claude/memory/`) з
  `~/.claude/projects/E--work-projects-other-mnemo/memory/`. Наслідок:
  нативного автозавантаження `MEMORY.md` більше немає — памʼять знаходиться
  **тільки пошуком** через MCP. Стара тека лишилась **застиглим бекапом**.
- **Хуків немає жодних** (рішення #27): ні `--with-memory-hook`, ні
  `--with-inject-hook`, ні самих команд. Дисципліна живе в одному місці —
  `.claude/rules/mnemo-memory.md`, і правило вимагає `search` **перед**
  кожним питанням, планом чи зміною, а не за списком тригерів.
- Поверхні HTTP: `/api/*` — приватний канал кабінету (прихований з OpenAPI);
  **`/mcp?token=<токен банку>`** — MCP для агентів, **без сегмента**: токен
  визначає банк і більше ніщо; `/mcp-admin` — керування банками, тільки
  сервісний токен; `/mcp-tools/<tool_name>` — дзеркало тулів звичайним HTTP для
  людини, видне у Swagger (`/docs`), віддає байт-у-байт той самий текст.
- Тули звуться `search`, `tree`, `reindex` — **без префікса** `memory_`: клієнт
  і так подає їх як `mcp__<server>__<tool>`.
- **Кожен банк має свій токен** (`banks.json`, 48 hex). Це least privilege, а не
  стіна: сервісний токен відкриває все.
- Ключ запису MCP, який пише `init`, — **`mnemo-memory`** (тули
  `mcp__mnemo-memory__search`); лишає місце для другого запису на інший банк.
  Старий ключ `mnemo` **перейменовується, а не доповнюється**: наш HTTP-запис
  переносить звичайний `init`, stdio-покоління — `--migrate`, чужий сервер із
  такою назвою не чіпається. Префікс змінних лишився `MNEMO_` навмисно.
- **Другий банк у проєкт кладеться руками з кабінету** — команди для цього
  свідомо немає; `init` означає рівно «памʼять цього проєкту». **Персональний
  лише токен** (`MNEMO_TOKEN`, `MNEMO_NOTES_TOKEN`) — інакше другий банк затер
  би токен першого; `MNEMO_HOST` / `MNEMO_PORT` спільні, бо це адреса **служби**,
  а не банку, і копія на кожен банк розходилася б щодо єдиного факту.
- **Правило `mnemo-memory.md` оновлюється тихо, якщо його не правили** — `init`
  звіряє sha256 байтів зі списком усіх редакцій, які mnemo писала (**дві форми
  на редакцію**: до `_write` файл ішов через `write_text`, тож Windows-проєкти
  мають CRLF). Невідомий хеш = чиясь правка, не чіпається. `MEMORY.md` — ніколи.
- **Список v2-проєктів зі `state/` не відновлюється в принципі**: імʼя файлу —
  `sha1(корінь)`, а v2-база **не має таблиці `meta`**. Джерело —
  `~/.claude.json` → `projects` (абсолютні шляхи). `~/.claude/projects/` не
  годиться: назви тек зводять `:`, `\` і `_` **усі** до `-`.
- **Ознака v2 на машині** — немає `banks.json`, але є `.db`. Однозначно й
  безпечно: без реєстру жоден індекс не належить живому банку. Інсталятор
  чистить їх через `clean-orphans --yes`, знімок робить **до** дзеркалення.
- **`bank_id` виводиться (sha1 кореня), токен видається.** Наслідок, який уже
  коштував вади: та сама тека завжди повертається з тим самим id, тож
  per-id стан у процесі (`_cancelled` у черзі) отруює наступний банк —
  `api_remove_bank` мусить знімати скасування й на гілці успіху.
- Кабінет: **усі дії банку — в одному меню `···`** у правому кінці рядка з
  назвою (синхронізація, повний реіндекс, доступ MCP, прибрати). Власних
  кнопок картка не має: саме той рядок кнопок зажимав ширину колонки з двох
  боків (<287px перенос, >311px документ вужчий за список файлів), тож
  обмеження зникло, а картка стала на чотири рядки нижчою. Діалог видалення
  веде **токеном**, не мегабайтами.
- `.mcp.json` **генерований і gitignored** — у git їде `.mcp.json.template` +
  `.mcp.env.example` + `mcp-setup.sh` / `.ps1`. **`init` будує цей шар сам, у
  будь-якому проєкті**; відстежений `.mcp.json` він не просто відкидає, а
  питає згоди й робить `git rm --cached` (без термінала — нічого, `--yes` для
  скриптів). Шаблон **починається з наявного `.mcp.json`**, інакше чужі
  сервери зникали б на першій перегенерації.
- **Скрипти динамічні**: підстановки вичитуються з шаблону, не перелічуються.
  Відсутня змінна = іменована помилка й ненаписаний файл (раніше — дослівний
  `{{TOKEN}}` у `.mcp.json` при `exit 0`). Новий банк = запис у шаблон + токен
  у `.mcp.env`, більше нічого. Дві половини (bash / PowerShell, бо нативній
  Windows нізвідки взяти bash) тримає тест на **байтову** рівність.
  Маркер `mnemo:dynamic-setup/1` відрізняє наш скрипт від чужого.
- **`_rule_state` = `edited` не означає «хтось правив руками»** — лише «байти
  не збігаються з жодною нашою редакцією». Забути дописати дайджест у
  `_RULE_SUPERSEDED` = мовчки вивести проєкт з-під оновлень правила. Так уже
  сталося: коміт про `mnemo-memory` оновив файл у репо й лишив константу
  казати `mnemo` (полагоджено, редакція **v6**).
- **Скіл `mnemo-adopt` лишається, але без опису проводки.** Він був другим
  source of truth про те, чим володіє `init`, — і протухав першим, бо ніщо
  його не перевіряє. Тепер: «`init` володіє проводкою повністю, читай його
  вивід». Скілу лишилися чотири судження, яких командою не зробити — тріаж
  `CLAUDE.md`, склад ролей, прапорець команд агентів, міграція вбудованої
  памʼяті.
- **README — вітрина, а не довідник**, і **пояснює до того, як ставити**:
  цикл «дописав → проіндексовано → знайдено за змістом», поняття банку,
  скріншот кабінету (`docs/cabinet.png`, знято з `devserver.py` на фікстурах —
  на живих даних не можна, там чужі шляхи й вміст), і аж тоді інсталяція.
  Таблиця «що пише `init`» лишається саме тому, що показує розкол: усе для
  колеги — в git, токен — ні.
- **Багатоклієнтність — наслідок форми, не фіча**: `stateless_http=True`, тож
  N консолей у тому самому проєкті = N зʼєднань до вже піднятої служби, без
  локу й без власника; банки — реєстр, тож сьомий проєкт коштує запис, а не
  другий резидент. **Віддалена служба в README свідомо не описана** (рішення
  користувача): архітектурно можлива — хост є змінною скрізь, — але живцем не
  піднімалась, і має дві межі, які роблять із неї не «просто інший хост»:
  `.md` мусять лежати **там, де служба** (watcher індексує свою ФС), і TLS
  немає — поза loopback це довірена мережа чи тунель. Писати, коли перевіримо.
- **`mnemo ui` друкує посилання й не відкриває браузер.** URL несе
  **сервісний** токен, а `webbrowser.open` віддав би його браузеру за
  реєстрацією в ОС і профілю, який там залогінений, — жодного з цих рішень
  команда CLI не ухвалює.
- **`isatty()` під Git Bash на Windows бреше** (True при `< /dev/null`) —
  для «чи є людина» потрібен `GetFileType == FILE_TYPE_CHAR`, як
  `IsInputRedirected` в `install.ps1`.
- Змінних **три**: `MNEMO_HOST`, `MNEMO_PORT`, `MNEMO_TOKEN` — плейсхолдер на
  кожній змінній позиції URL. Хост додано, бо `MNEMO_API_HOST` налаштовний, а
  літерал у git-трекнутому шаблоні не перевизначався. Дописує їх **звичайний**
  `init` разом із рядком `sed`; без цього плейсхолдер іде в `.mcp.json`
  дослівно, а скрипт виходить з 0.
- Індекс зветься `sha1(корінь)[:16].db` — звʼязок односторонній, тож зняті
  банки лишають **осиротілі** файли в `state/`. `doctor` їх рахує,
  `clean-orphans` видаляє (питає перед тим); автоматично — ніколи.

- **Схема системи** — `docs/schema.html`: одна сторінка з діаграмами (дві
  служби, чотири поверхні за токенами, конвеєр `.md → вектори`, пошук, диск).
  **Похідна від чотирьох доків v3, не пʼятий source of truth** — нічого не
  має існувати тільки там. Опублікована приватним артефактом:
  `https://claude.ai/code/artifact/3699278b-bc10-455b-a2a7-2462efb725c9`.

- Встановлення — **два рівні**: інсталятор (`install.ps1` / `install.sh`) =
  вся машина однією командою, аж до `doctor`; `mnemo init` = окрема команда
  на теку проєкту. Зупиняти сервіс руками перед оновленням **не треба** —
  інсталятор сам робить `stop → refresh → start`.
- Знесення — **дзеркало інсталятора**: `uninstall.ps1` / `uninstall.sh`,
  за замовчуванням усе разом із моделлю; `-KeepModel` / `-KeepState` /
  `-DryRun` / `-Yes`. `HOME` і linger не чіпає ніколи. Єдине, що не
  відновлюється з `.md`, — `banks.json`, тож банки друкуються перед
  видаленням, а після перевстановлення потрібен новий `init` у кожному проєкті.
- **Оновлення на місці не перевіряє обіцянку «клонуй і постав»** — воно
  працює на вже зарезолвленому venv. Перевіряє лише встановлення **з нуля**;
  так і знайшлася зламана залежність, невидима для всіх, хто вже мав рушій.
  Тому **мажори пінуються**: `mcp>=2.0,<3` (рішення #29).
- MCP-клас у SDK 2.0 зветься **`MCPServer`** (`mcp.server.mcpserver`), у 1.x був
  `FastMCP`. `stateless_http` / `streamable_http_path` переїхали в
  `streamable_http_app(...)`, а `session_manager` **кидає**, поки той не
  викликано — тримається на тому, що `api` монтує обличчя на імпорті.
- `mnemo service start` **чекає на `/health`**: «started» означає «відповідає».
  Готовність визначає `/health`, **не** живучість породженого PID — на Windows
  це заглушка-редиректор, яка вмирає, поки бекенд працює.

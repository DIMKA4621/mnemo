# mnemo project memory

Bank root: `.claude/memory` (this folder), searchable through the `mnemo` MCP
server — the `search` tool. This file is an **index**: links + quick facts only;
detail lives in `topics/`, day notes in `logs/`.

## Architecture

- [Поверхні служби](topics/service-surfaces.md) — чотири обличчя. **`/api/*`
  (кабінет+CLI) типово ВІДКРИТИЙ, без токена** (2026-08-21, рішення #34) —
  єдиний виняток; `/mcp?token=<токен банку>` без сегмента (токен визначає
  банк і більше ніщо), `/mcp-admin` під сервісним токеном, `/mcp-tools/*` як
  байт-у-байт дзеркало для людини — усі три незмінно за токеном. Там же:
  токен на банк, `bank_id` виводиться а токен видається (вада з
  `_cancelled`), багатоклієнтність як наслідок `stateless_http`, і чому
  `MCPServer` у SDK 2.0 тримається на монтуванні під час імпорту.
- [Проводка проєкту](topics/project-wiring.md) — що `init` кладе в чужий
  репозиторій: ключ `mnemo-memory` (старий `mnemo` **перейменовується, не
  доповнюється**), `.mcp.json` генерований і gitignored проти шару
  template + `.mcp.env` + `mcp-setup.*`, **динамічні** підстановки (відсутня
  змінна = помилка, а не дослівний `{{TOKEN}}` при `exit 0`), оновлення
  правила за sha256, `git check-ignore -v` після seed (broad `.claude` більше
  не ховає memory мовчки) і чому `edited` ≠ «правили руками». Хуків немає.
- [Встановлення й життєвий цикл](topics/install-lifecycle.md) — два рівні
  (інсталятор = машина, `init` = тека), знесення як дзеркало, осиротілі
  індекси, ознака v2 і чому список v2-проєктів не відновлюється. Головне:
  **оновлення на місці не перевіряє обіцянку «клонуй і постав»** — звідси
  піновані мажори (`mcp>=2.0,<3`, рішення #29).
- [Кабінет](topics/cabinet-ui.md) — вибір теки обходить ФС на боці бекенда
  (`webkitdirectory` шляху не дає), усі дії банку в одному меню `···`,
  налаштування як **екран, а не модалка** (затемнений фон показував би
  застарілий стан), окремий warning lane для `REBUILD PENDING` і structured
  «Обслуговування»: CLI/UI читають один doctor-report, cleanup приймає лише
  щойно показані orphan id. **Нова оболонка реалізована** у
  `src/webui/static/` (сайдбар = три маршрути, хедер = сторінка, підвал
  сайдбару = машина) з `docs/cabinet-design.html` як еталоном; `app.js`
  розбитий на `shell.js`/`page-{memory,journal,settings}.js`, CSS — на
  `styles/*.css`. Journal snapshot-текст, кнопка завантаження моделі й
  чекбокс `init` у діалозі банку **зроблені** 2026-08-20 (друге) —
  `logs/2026-08-20-cabinet-followups.md`. Не зроблено: фільтр статусу й
  повнотекстовий пошук журналу.
- [Native Windows support](topics/windows-native-support.md) — PowerShell 5.1
  installer, canonical launcher contract, portable wiring, and verification.
- [Пропускна здатність ембедингу](topics/embedding-throughput.md) — наш
  CPU-резидент проти bge-m3 на GPU через Ollama, на однакових 35 571 токені:
  **8.8× на пакеті, але лише 1.8× на одному запиті**. Головна знахідка:
  **час індексації = паддед-токени / 243** — але це властивість **CPU**-
  бекенда, на GPU домінує кількість викликів. Звідси реалізоване
  `index.plan_batches` (**≈1.6×** на перебудові) і те, що бюджет батча
  **мусив стати по-провайдерним**: виграшне CPU-число робить GPU **удвічі
  повільнішою**, і помилка мовчазна.
  Там же — чому `CHUNK_CAPACITY` тримає максимум під вікном e5 у 512
  токенів, і recall трьох пар (модель × рантайм): **усі три однакові, бо
  `test_search.py` — поріг регресії, а не інструмент порівняння**.
- [Якість пошуку: вади й черга робіт](topics/search-quality.md) — **лексична
  нога пошуку була мертва** (`_fts_escape` робила з запиту фразу → 0 хітів на
  будь-якому питанні). Виправлено, і `tests/eval_search.py` це довів: арма зі
  старим кодом збігається з чистим вектором **у всіх шести метриках**. Рівна
  вага при цьому шкодить — правильна роль лексики це **переранжування
  векторних кандидатів**, вага ~6:1. Там же: стеля чанка в символах не
  обмежує токени, 5% чанків — голі заголовки, справжня причина «плаваючого
  404» від MCP, порядок робіт і що вирішено НЕ робити.
- [Машинні налаштування і другий провайдер](topics/provider-settings.md) —
  `state/settings.json` **реалізовано** (`src/settings.py`, `GET`/`PUT
  /api/settings`, контракт §6.6): env > файл > дефолт, і кожне значення
  несе своє `source`, бо збережене може бути інертним. Усе віддає **функція**
  — константа при імпорті тут не працює, і ця вада вже лежала в
  `providers/api.py`. Там же: Ollama як конфігурація `api`, чому зміна
  провайдера **завжди** тягне перебудову (збіг `dim` — найнебезпечніший
  випадок, підтверджено живцем), керування резидентом, і чому Docker поки ні.
- [Відкладене й черга робіт](topics/deferred.md) — що вирішено зробити пізніше
  і чому саме в такому порядку; там же дрібні вади наскрізної перевірки й
  рішення, які лишились за користувачем.
- [Самооновлення рушія — дизайн](topics/engine-self-update-design.md) —
  **ПОВНІСТЮ ЗАВЕРШЕНО** 2026-08-21, усі 13 кроків плану реалізовані,
  перевірені й закомічені на `feat/v3` (19 комітів, `3cf33e7`…`4e1faf4`,
  не запушені). Поза наявними фазами 0–7 доки (design decision #33
  у `Memory-design-v3.md` §13), повний контракт — `Memory-contracts-v3.md`
  §9.9 (`/api/update/*`), FR-10 у `Memory-requirements-v3.md`. Теги/релізи
  GitHub (не HEAD master), напівавтоматика (фоновий check, застосування —
  людський клік), версійні теки `versions/<tag>/` з окремим venv на
  кожну (спільний venv уже раз ламав свіжий інстал, рішення #29), junction/
  symlink `current`, health-gated rollback з автоматичним відкатом.
  **Знайдено й виправлено шість реальних багів**, усі того самого
  сімейства — код, писаний для світу з одним статичним venv, тихо
  припускав "я і є той venv/той код": (1) `sys.prefix` замість
  `sys.argv[0]` у лаунчері, (2) застиглий `sys.executable` у
  `service_ctl.start()`, (3) застиглий `cwd` там же (новий код зі старим
  `cwd` = стара версія мовчки виконувалась попри новий venv), (4)
  `update-apply` убивав сам себе через `taskkill /T` на власне дерево
  процесів, (5) **найкритичніший** — `stage_release` білдив у staging-
  теці й переміщував її, ламаючи pip-зашитий shebang усіх console-script
  exe (кожне успішне самооновлення ламало команду `mnemo`), (6) `bin\`
  launcher exe ніколи не перевидавався на switch, тож рано чи пізно
  ламався сам собою через retention. Плюс менші: протухання
  `update_available`, race у записі `service.pid`, POSIX-інсталятор
  мігрований лише наполовину (двічі — install і uninstall). Повна
  консолідована перевірка: **536 тестів пройдено**. Детальна історія по
  кроках — у `logs/2026-08-2[01]-engine-self-update-*.md` (13 файлів).
  Реальний рушій користувача (`~/.claude/mnemo`) **ще не мігрований** на
  нову розкладку — фіча готова, живий перехід попереду, окрема дія.

## Quick facts

- Памʼять цього проєкту **переїхала в репозиторій** (`.claude/memory/`) з
  `~/.claude/projects/E--work-projects-other-mnemo/memory/`. Наслідок:
  нативного автозавантаження `MEMORY.md` більше немає — памʼять знаходиться
  **тільки пошуком** через MCP. Стара тека лишилась **застиглим бекапом**.
- Тули звуться `search`, `tree`, `reindex` — **без префікса** `memory_`: клієнт
  і так подає їх як `mcp__<server>__<tool>`.
- **Чим міряти якість пошуку:** `tests/eval_search.py` — 64 кейси на цьому
  банку, кожна нога окремо. Розмітка — **дослівна фраза, не шлях**: переживає
  перечанкування й не гниє мовчки. Не `test_*` навмисно (потребує моделі й
  саме цієї памʼяті). База: vector 0.51 MRR / 0.75 r@10; краще сьогодні —
  0.54 / 0.81. `test_search.py` лишається порогом регресії, не інструментом
  порівняння.
- Індекс зветься `sha1(корінь)[:16].db`; звʼязок односторонній, тож зняті банки
  лишають осиротілі файли. `src/diagnostics.py` — **одне** structured джерело
  для CLI doctor й кабінету; cleanup явний і приймає тільки показані id,
  перечитуючи registry двічі. Автоматично — ніколи.
- **Стан банку — одне поле `state`** (`enabled|frozen|disabled`), не пара
  булеанів: `banks.json` редагують руками, а два поля про один факт розходяться.
  `frozen` — не стежимо, **але шукається**. `Bank.enabled` лишилась
  **обчислюваною** property (плюс `watched` / `searchable`), тож стан задається
  тільки через `state`.
- **Ollama: `keep_alive` працює лише на нативному `/api/embed`.** На
  OpenAI-сумісному `/v1/embeddings` поле приймається й **мовчки ігнорується**
  (виміряно). Будь-яка перевірка «чи модель у пам'яті» — `GET /api/ps`, не
  припущення з коду відповіді.
